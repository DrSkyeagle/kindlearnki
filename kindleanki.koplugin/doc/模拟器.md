# 在 Windows 上模拟跑 Kindle Voyage 固件（eink-emulator）

> 2026-10-30 实测：**能跑**。KV 5.13.6 真固件在 QEMU 里启动到 Home，
> KOReader kindlepw2 v2026.07.1 起来并加载本插件，
> `model=KindleVoyage html=ok sqlite=ok zstd=ok ca=yes`。
> 本文记录可复现步骤与三个必须先绕过的坑。

## 1. 环境

- 宿主：Windows 11 + WSL2（本机 `KO-test`，Ubuntu 24.04，12 核 / 15 GB）
- 工具：[katadelos/eink-emulator](https://github.com/katadelos/eink-emulator)
  （QEMU fork，machine `imx6sl-wario` / `board=icewine`，512M，`ar6003-sdio` Wi-Fi）
- 依赖：`build-essential ninja-build pkg-config libglib2.0-dev libpixman-1-dev
  libslirp-dev python3-venv e2fsprogs zstd libarchive-dev libssl-dev`，
  以及源码编译的 [KindleTool](https://github.com/NiLuJe/KindleTool)

## 2. 一次性搭建（约 25 分钟）

```bash
# 依赖
sudo apt update && sudo apt install -y build-essential ninja-build pkg-config \
  libglib2.0-dev libpixman-1-dev libslirp-dev python3-venv e2fsprogs zstd \
  libarchive-dev libssl-dev

# KindleTool（导入固件 + --mrpi 解包都要它）
git clone --depth 1 https://github.com/NiLuJe/KindleTool.git
make -C KindleTool -j12
ln -sf "$PWD/KindleTool/KindleTool/Release/kindletool" /usr/local/bin/kindletool

# eink-emulator（qemu 子模块是 SSH URL，无 key 时先改写）
git config --global url."https://github.com/".insteadOf "git@github.com:"
git clone --depth 1 https://github.com/katadelos/eink-emulator.git
cd eink-emulator && git submodule update --init --depth 1
python3 -m venv .venv && . .venv/bin/activate && pip install -e .
./eink build                     # 只编 arm-softmmu + aarch64-softmmu，12 核约 15 分钟
```

## 3. 建实例并启动（约 3 分钟）

```bash
./eink versions --model kindle-voyage          # 5.13.6 是 KV 末版
./eink create kv --model kindle-voyage --firmware 5.13.6 --mrpi

# ★ 坑 1：必须关掉 watchdog action，否则访客看门狗一响，
#   配合 -no-reboot 直接把 QEMU 结束（表现：跑几分钟进程没了）
./eink run kv --headless --qmp-socket --serial-socket -- -watchdog-action none
```

串口日志 `machines/kv/kv.serial.log`；QMP 截图：

```bash
python3 scripts/eink-qmp.py --machine kv screendump /tmp/kv.ppm   # .png 需 libpng
```

## 4. 装 KOReader + 插件

```bash
# 宿主机解压（不要在访客里 unzip：TCG 下太慢，会触发看门狗）
unzip -q koreader-kindlepw2-v2026.07.1.zip -d ko
tar -cf - -C ko koreader | ssh -i build/ssh/id_ed25519 -p 2222 root@127.0.0.1 \
    "tar -C /mnt/us -xf -"                                   # 88 MB / 约 3.5 分钟
tar -cf - -C /mnt/d/ankindle kindleanki.koplugin | ssh -i build/ssh/id_ed25519 \
    -p 2222 root@127.0.0.1 "tar -C /mnt/us/koreader/plugins -xf -"

# ★ 坑 2：koreader.sh 第一件事就是 `echo unlock > /proc/keypad`，
#   而模拟器的 fsr_keypad I2C 不应答，该写操作永久 D 状态 → 启动器卡死。
#   绕法：停框架后直接起 reader.lua
ssh ... "stop lab126_gui"
ssh ... "cd /mnt/us/koreader && KOREADER_DIR=/mnt/us/koreader \
         setsid nohup ./luajit ./reader.lua >/tmp/ko2.log 2>&1 </dev/null &"
```

启动约 40 秒后截图即可看到 KOReader 与 `kindleanki: … model=KindleVoyage` 日志。

## 5. 已知坑与限制

1. **看门狗**（必须处理）：`-watchdog-action none`。根因是 TCG 慢 + 块层写放大，
   访客 `ksoftirqd` 被饿死 >12 s 就触发 pre-timeout，默认 action=reset。
2. **`/proc/keypad` 写阻塞**：启动器必经路径，模拟器未实现 fsr_keypad 的 I2C 应答。
   绕过=直接跑 `reader.lua`；长期方案是给启动器加个「设备可写性探测」或
   在模拟器侧补 keypad 模型。
3. **内存紧**：框架在跑时 485/512 MB 已用满；`stop lab126_gui` 后降到 ~356 MB。
   KOReader 必须停框架跑，否则 512 MB 下余量不足。
4. **触摸注入未打通**：QMP 里有 `Cypress TrueTouch Gen4 (absolute)` 输入设备，
   但 `input-send-event` 的 abs/btn 事件没有到达访客 `/dev/input/event1`；
   `tap` 子命令只支持 Bellatrix。待办：找对 QOM 路径，或起 WSLg 窗口 + `xdotool`。
5. **性能不可用**：纯 TCG，同步耗时、TLS 握手耗时、翻页延迟都不能当结论。
6. 磁盘写入用 `cache=writethrough`；访客被强杀可能丢 `/mnt/us` 最近写入
   （实测一次 88 MB 拷贝后目录只剩 6 项，重拷即恢复）。
